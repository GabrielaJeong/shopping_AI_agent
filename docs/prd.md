# 무디핏(MoodFit)

<aside>
💡

**무디핏(MoodFit), 취향에 꼭 맞는 옷을 골라주는 AI 패션 초개인화 추천 앱**

패션 커머스 도메인 / 개인화 추천 + LLM 챗봇 / 0→1 사이드 프로젝트 B

</aside>

## 1. 개요

### 1.1 문제 정의

패션 커머스에서 사용자는 수많은 상품 속에서 자기 취향에 맞는 것을 찾기 어렵다.

1. 기존 추천은 **"왜 이게 추천됐는지"가 불투명함.**
   1. 사용자는 추천을 신뢰하기 어렵고, 빗나간 추천을 교정하기도 어려움
   2. 알고리즘 수정을 여러 아이템을 누르고 좋아요를 클릭하는 방식으로 사용자가 직접 해야하는 경우도 있음
2. 검색은 **정확한 키워드를 알아야만 작동함.**
   1. "더 라이트한 느낌으로", "이거랑 비슷한데 더 저렴한 걸로"처럼 막연하고 상대적인 표현으로 좁혀가고 싶은 욕구를 적용하기 어려움

### 1.2 목표

**개인화 정확도를 1순위 목표**로, 다음 두 가지가 핵심 차별점.

- **설명 가능한 추천**: 모든 추천에 **"왜 추천했는지"(reason)**를 함께 제공한다.
- **AI 대화로 탐색 좁히기**: 자연어 발화를 **추천을 다시 정렬하는 신호(재랭킹 조건)로 사용**한다.

### 1.3 타겟 사용자

- 자기 취향은 있지만 키워드로 정확히 표현하기 어려운 패션 쇼핑 사용자
- 추천을 받되 신뢰 여부를 판단하고 싶어 하는 사용자
- "이게 아닌데…." 싶을 때 대화로 즉시 방향을 틀고 싶어 하는 사용자

### 1.4 핵심 가설

추천에 **근거(reason)**를 보여주고, 대화로 **다시 정렬되게 하면**, 사용자는 **추천을 신뢰하고 더 깊이 탐색할 수 있으며**, 그 과정에서 쌓인 **행동이 다시 개인화 정확도를 높이는 선순환**이 발생한다.

## 3. 시스템 아키텍처 개요

시스템은 **4개 계층**과 **2개의 루프**, 그리고 콜드스타트 기본 상태로 구성됨

!image.png

### **3-1. 계층**

- **데이터 계층**
  - 이벤트 수집(클릭·조회·구매), 상품 카탈로그(match·reason 생성 원천), 유저 취향 벡터(가중치 프로필)
- **추천 파이프라인**
  - 후보 생성 → 랭킹 모델 → (콜드스타트 폴백)
- **서비스 계층**
  - LLM 챗봇, 추천 UI
- **사용자 인터랙션**

### **3-2. 루프**

- **재랭킹 루프** $\footnotesize{\colorbox{#e8dfd8}{Short-term}}$
  - 챗봇이 **발화를 재랭킹 조건**으로 올리고 → 랭킹이 **다시 정렬**한 결과(match·reason)를 받아 → 노출
  - 대화 안에서 즉석으로 완료되는 루프!
- **피드백 루프 $\footnotesize{\colorbox{#e8dfd8}{Long-term}}$**
  - 사용자 행동이 취향 벡터로 환류되어 → 다음 추천을 바꿈
  - 프로필에 누적된다.

<aside>
💡

**콜드스타트는 예외가 아니라 기본 출발 상태**로 설계. 출시 시점엔 데이터가 거의 없으므로 **콘텐츠+규칙 기반으로** 100% 동작을 시작하고, **데이터 성숙도에 따라** 협업 필터링(CF)·학습 모델로 **단계적으로 전환합니다.**

</aside>

## 4. 기능 명세

### F1. 온보딩 & 취향 벡터 시드

**목적**: 행동 이력이 없는 신규 유저(신규 유저 콜드스타트)에게 추천을 시작할 초기값을 만든다.

**동작**: 가입 직후 5단계 취향 선택(스타일·톤·핏 등 태그 선택)을 거친다. 선택 결과를 태그별 가중치로 변환해 **취향 벡터의 초기값**으로 심는다. 이 벡터가 이후 피드백 루프의 출발점이 된다.

**입력 / 출력**

- 입력: 온보딩 선택값(태그 집합)
- 출력: 초기 취향 벡터 (예: `{미니멀: 0.7, 베이지: 0.6, ...}`)

**콜드스타트 동작**: 온보딩 자체가 신규 유저 콜드스타트 대응책. 온보딩을 건너뛴 사용자는 인기·신상 규칙 기반 추천으로 시작한다.

**수용 기준**

- 온보딩 완료 시 취향 벡터가 생성되어 첫 추천에 즉시 반영된다.
- 온보딩 미완료 시에도 빈 화면 없이 규칙 기반 추천이 노출된다.

**지표**: 온보딩 완료율, 온보딩 직후 첫 세션 CTR

---

### F2. 후보 생성 (Candidate Generation)

**목적**: 전체 카탈로그(수만 개)에서 랭킹에 넘길 후보(수백 개)를 빠르게 추린다. 정밀도보다 **재현율(놓치지 않기)과 속도**가 중요한 단계.

**동작**: 데이터 성숙도에 따라 전략을 단계적으로 전환한다.

- 출시 단계: **콘텐츠 기반**(상품 태그·속성과 취향 벡터의 유사도)을 1차 후보 생성기로 사용. 데이터가 없어도 즉시 동작하고 신규 상품 콜드스타트에 강하다.
- 동시 운용: **규칙 기반**(인기·신상·카테고리)을 콜드스타트 폴백 및 안전망으로 사용.
- 데이터 축적 후: **협업 필터링(CF)** 을 추가해 콘텐츠 기반의 약점인 의외성(필터버블)을 보완.

**입력 / 출력**

- 입력: 취향 벡터, 상품 카탈로그, (선택) 현재 맥락
- 출력: 후보 상품 집합 (수백 개)

**콜드스타트 동작**: 콘텐츠 기반은 상호작용 데이터 없이 태그만으로 신규 상품을 매칭할 수 있어 신규 상품 콜드스타트를 해결한다. 신규 상품에는 탐색 노출 슬롯을 별도 배정해 초기 데이터를 수집한다.

**수용 기준**

- 어떤 사용자 상태에서도 후보 집합이 비지 않는다(규칙 기반 폴백 보장).
- 후보 생성 단계에서 응답 지연이 정해진 임계값 이내다.

**지표**: 후보 집합의 재현율(최종 클릭 상품이 후보에 포함된 비율), 응답 시간

### F3. 랭킹 모델 & match·reason 생성

!image.png

#### **목적**

후보 수백 개를 정밀하게 줄 세워 `match` 점수와 `reason` 문구를 산출함. **\*정밀도 집중 고려**

#### **동작**

`match` 점수는 단일 값이 아니라 **여러 신호의 가중 합**을 0~100으로 정규화한 결과다.

| **피처**        | **의미**                     | **예시 가중치(출시 단계, 수동)** |
| --------------- | ---------------------------- | -------------------------------- |
| **취향 유사도** | 취향 벡터 ↔ 상품 태그 매칭   | 0.5                              |
| **인기·전환**   | 판매량, 클릭률               | 0.2                              |
| **최근 맥락**   | 최근 본 상품·세션 맥락       | 0.2                              |
| **챗봇 조건**   | **재랭킹 조건**(F4에서 유입) | 0.1                              |

`reason` 문구는 별도로 생성하지 않고 **가장 크게 기여한 피처를 템플릿으로 변환**한다.

> 예: 취향 유사도가 최대 기여 → "평소 좋아하시는 카멜 톤 + 유사한 실루엣이에요"

#### **점수화 방식 진화**

- 출시 단계
  - 피처 가중치를 사람이 정한 **가중합**. 단순하고 설명이 쉽다.
- 데이터 축적 후
  - 클릭·구매 데이터로 **학습 기반 랭킹**(GBDT/LightGBM, learning-to-rank)으로 전환. 가중치를 데이터가 학습

#### **입력 / 출력**

- 입력: 후보 집합, 취향 벡터, 최근 맥락, (선택) 재랭킹 조건
- 출력: 정렬된 추천 리스트 + 각 상품의 `match`(0~100), `reason`(문구)

#### **수용 기준**

- 모든 추천 상품에 `match`와 `reason`이 함께 부여된다.
- `reason`은 실제 최대 기여 피처를 반영(임의 생성 금지)

#### **지표**

- [ ] 상위 노출 상품의 CTR/전환율
- [ ] reason 유효성

### F4. LLM 챗봇 재랭킹

**목적**

사용자의 자유 텍스트 발화를 추천을 다시 정렬하는 **재랭킹 조건**으로 변환한다. 이 프로젝트의 핵심 차별점.

**동작 (왕복 흐름)**

1. 사용자가 "더 라이트하게", "예산 10만원 이하로" 등 발화.
2. 챗봇이 **맥락을 읽는다**: 취향 벡터·현재 보고 있는 상품·최근 본 상품. ("비슷한 톤"이 무엇 대비 비슷한지 해소하기 위함.)
3. 발화 + 맥락을 **구조화된 재랭킹 조건**으로 변환(톤·가격대·실루엣 제약 + 가중치 조정값).
4. 재랭킹 조건을 **랭킹 모델로 올려보낸다(↑)**.
5. 랭킹 모델이 기존 취향 벡터에 조건을 얹어 재정렬 → 새 `match`·`reason`을 **돌려받는다(↓)**.
6. 결과를 추천 카드로 사용자에게 노출.

> ⚠️ 방향 주의: 챗봇이 올려보내는 것은 **점수가 아니라 조건**이다. `match`·`reason`은 랭킹이 돌려주는 **결과**다. 챗봇 ↔ 랭킹은 양방향이다.

**입력 / 출력**

- 입력: 사용자 발화, 사용자 맥락(취향 벡터·현재 상품)
- 출력: 재랭킹 조건(랭킹으로) / 추천 카드(사용자로)

**진화 경로**

- 출시 단계: 키워드 + LLM 의도 파싱으로 조건 추출(프로토타입의 키워드 라우팅을 LLM 기반 의도 추출로 대체).
- 이후: 멀티턴 맥락 누적, 더 정교한 제약·가중치 매핑.

**수용 기준**

- 발화가 실제 추천 결과의 재정렬로 이어진다(고정 응답 금지).
- 맥락이 모호할 때 챗봇이 되묻거나 합리적 기본값을 적용한다.

**지표**: 재랭킹 사용률, 재랭킹 후 클릭/전환율, 멀티턴 지속률

### F5. 추천 UI & 피드백 시트

**목적**: 추천 결과를 노출하고, 사용자가 피드백을 줄 수 있는 표면을 제공한다.

**동작**: 홈·상세·리스트에 추천 카드를 `match`·`reason`과 함께 노출한다. 사용자가 피드백을 주면 "취향에 반영했어요" 시트로 **무엇이 어떻게 반영됐는지 시각화**한다(개인화 학습을 사용자에게 보여줌).

**입력 / 출력**

- 입력: 정렬된 추천 리스트(match·reason)
- 출력: 화면 노출 + 사용자 행동 신호(클릭·저장·좋아요·스킵 등)

**수용 기준**

- 카드에 match·reason이 항상 함께 표시된다.
- 피드백 직후 반영 결과가 사용자에게 가시적으로 표시된다.

**지표**: 카드 단위 인터랙션율, 피드백 시트 노출 후 행동 변화

---

### F6. 피드백 루프 & 취향 벡터 갱신

**목적**: 사용자 행동을 취향 벡터로 환류시켜, 쓸수록 개인화 정확도가 높아지게 한다(장기 루프).

**동작**

1. **신호 가중치**: 모든 행동을 같게 치지 않는다. 강한 확신일수록 큰 델타.

| 신호               | 상대 강도     | 부호 |
| ------------------ | ------------- | ---- |
| 구매               | 가장 높음     | +    |
| 저장               | 높음          | +    |
| 좋아요             | 중            | +    |
| 체류 시간(오래 봄) | 낮음(암묵)    | +    |
| 클릭               | 가장 낮음(약) | +    |
| 스킵 / 숨김        | —             | −    |

1. **부호 있는 델타**: 행동을 델타로 변환해 관련 태그의 가중치를 올리거나(+) 내린다(−). 무관한 태그는 그대로. (예: 베이지·미니멀 셔츠 좋아요 → 미니멀·베이지 가중치 +0.08)
2. **정규화 + 감쇠**: 벡터가 도착해 갱신될 때 처리한다. 정규화로 가중치가 무한정 커지지 않게 범위를 묶고, 시간 감쇠로 옛 취향을 조금씩 깎아 최근 행동을 우선한다. ("취향은 변한다"를 시스템이 반영.)
3. **갱신 주기**: 가벼운 가중치 업데이트는 실시간(반영 결과 즉시 노출), 무거운 재학습(CF 행렬 등)은 야간 배치.

**입력 / 출력**

- 입력: 사용자 행동 신호
- 출력: 갱신된 취향 벡터(다음 추천에 사용)

**수용 기준**

- 긍정·부정 신호가 모두 벡터에 반영된다(부정 신호 누락 금지).
- 정규화·감쇠로 벡터가 발산하거나 낡지 않는다.
- 실시간 경로와 배치 경로가 명확히 분리된다.

**지표**: 취향 벡터 수렴 속도, 갱신 전후 추천 정확도 변화

## 8. 용어집

- **취향 벡터(taste vector)**: 한 사용자의 취향을 태그별 가중치 숫자 묶음으로 적어둔 프로필. 예: `{미니멀: 0.72, 베이지: 0.55, ...}`
- **델타(Δ)**: 변화량. 행동 하나가 취향 벡터의 숫자를 얼마나 움직이는지. 긍정은 +, 부정은 −(부호 있는 델타).
- **유사도**: 두 벡터가 얼마나 닮았는지를 잰 값. 취향 벡터와 상품 벡터가 닮을수록 추천 근거가 강하다.
- **가중치**: 중요도를 숫자로 매긴 것. (1) 취향 벡터 안의 선호 강도, (2) match 점수 산출 시 각 피처의 중요도, 두 의미로 쓰인다.
- **가중합**: 각 값에 가중치를 곱해 모두 더한 것. match 점수의 출시 단계 산출 방식.
- **후보 생성 / 랭킹**: 빠르게 수백 개를 추리는 거름망(후보 생성) → 그것만 정밀하게 줄 세우기(랭킹)의 2단계 구조.
- **콜드스타트**: 데이터가 없을 때 어떻게 시작하느냐의 문제. 신규 유저·신규 상품·신규 서비스 세 종류.
- **정규화 / 감쇠**: 벡터가 발산하지 않게 범위를 묶는 것(정규화) / 시간이 지나면 옛 취향을 깎아 최근을 우선하는 것(감쇠).
