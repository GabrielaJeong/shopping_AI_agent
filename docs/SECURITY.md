# SECURITY.md

> Moodyfit 보안 정책·방어 기법. 로그인·개인 취향 데이터를 다루므로 필수.
> 빈 스켈레톤으로 시작 — 인증/저장 구현이 정해지면 항목을 채운다.

## 위협 모델 / 보호 대상

- 보호 대상: 사용자 계정 자격증명, 개인 취향 벡터·행동 신호(클릭/저장/구매 등 개인 데이터).
- ( 구체 위협·신뢰 경계는 인증 방식 확정 후 기록 )

## 인증 / 세션

- 로그인 옵션(정본): 이메일 / Apple / 카카오 / 게스트(둘러보기).
- ( Apple/Kakao는 실제 SDK 연동 시 공식 브랜딩·보안 가이드 준수. 세션/토큰 정책은 확정 후 기록 )

## 비밀 / 환경변수

- production 필수 비밀이 없으면 **부팅 시 검증·없으면 종료**. 조용한 insecure fallback 금지.
- ( LLM/외부 API 키 관리 방식은 연동 단계에서 기록 )

## 개인정보 / 데이터 취급

- ( 취향 데이터 저장 위치·보존·삭제(취향 다시 설정/로그아웃) 정책 확정 후 기록 )

## 입력 검증 / API 라우트

- ( 신뢰 경계에서의 검증 위치·형식. CONVENTIONS와 정합 )

## 외부 리뷰 수용 원칙

- 보안 critical finding이라도 무비판 묶음 적용 금지 — 범위가 틀렸다면 반박. critical과 부수 제안 분리 적용.
